# 顾客与关卡系统

> 所属项目：一起开猫店
> 总文档：[README.md](README.md)

---

## 1. 顾客系统

- 容器**上方同时显示最多 3 位活跃顾客**，各自头顶气泡显示需求（M1：以设计稿 game.html 为准）
- MVP：2-3 种固定猫咪形象，随机出场（v1.3 扩展为颜色/衣服/配饰随机组合）
- 某位送餐完成 → 满意动画 → 离开 → 队列下一位补位入场

---

## 2. 难度渐进策略

| 回合 | 顾客数 | 需求类型 | 最高需求等级 | 示例 |
|------|--------|---------|------------|------|
| 1-3 | 1-2 个 | 单一需求 x1 | Lv3 | 1个泡芙 |
| 4-7 | 2-3 个 | 单一需求 x1-2 | Lv4 | 2个铜锣烧 |
| 8-12 | 3-4 个 | 多数量需求 | Lv5 | 3个鲷鱼烧 |
| 13-18 | 3-5 个 | 组合需求 | Lv6 | 1个瑞士卷 + 2个泡芙 |
| 19+ | 4-6 个 | 组合需求 | Lv7 | 1个蛋糕卷 + 2个鲷鱼烧 + 1个曲奇 |

> 中后期关卡（4-10关）难度需适当提高，以驱动道具使用率达到 ≥30%。

---

## 3. 通关与失败

- **通关条件**：服务完当前回合所有顾客
- **失败条件**：容器溢出警戒线超过 5 秒
- **通关结算**：得分 → 星级评价（1-3 星），采用**分数阈值制**：
  - 通关即保底 **1 星**
  - 得分 ≥ `star2Score` → **2 星**
  - 得分 ≥ `star3Score` → **3 星**
  - 每关的阈值在关卡 JSON 中配置（见下方 §4）
- **通关结算页显示本关好友分数排名**，激励重玩和分享
- **失败选项**：重新挑战 / 看广告复活（清除容器上半部分元素）

**关卡名称**（对应设计稿 `home.html` 关卡选择卡的「草莓季 · 午后」大字）：
- 命名规律：`「主打甜点 / 季节主题」 · 「时段或天气」`，随关卡推进呈「清晨 → 午后 → 黄昏 → 星夜 → 庆典」的一日/季节弧线，主打甜点大致对应该关的最高需求等级。
- 首页关卡卡呈现：顶部小字「第 N 关 · 共 10 关」+ 中部大字关卡名 + 星级。
- ⚠️ **字体子集**：内嵌中文字体 `ZCOOLKuaiLe` 为压包体已裁成子集，新增/改动关卡名后必须重跑 `scripts/subset_font.py`（它自动扫描 `levels.json` 纳入新字形），否则未覆盖的字会显示成豆腐块。完整原件见 `…/ZCOOLKuaiLe-Regular.ttf.orig`。

### JSON 配置示例（第 5 关）

```json
{
  "round": 5,
  "name": "鲷鱼烧夜市 · 傍晚",
  "customers": [
    { "demands": [{ "level": 8, "count": 1 }] },
    { "demands": [{ "level": 4, "count": 2 }] },
    { "demands": [{ "level": 5, "count": 1 }] }
  ],
  "dropRange": [1, 3],
  "star2Score": 2000,
  "star3Score": 3200
}
```

> `name`：关卡主题名（必填，非空）；首页关卡卡展示。
> `star2Score` / `star3Score`：2 星和 3 星的分数阈值。3 星需要在服务顾客之外额外合成高等级甜品获取分数。
