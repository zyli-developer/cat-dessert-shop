# 抖音小游戏 安全区 / 胶囊 适配说明

> 目的：解决「开发者工具 / 真机预览样式与设计稿不一致、右上角 HUD 被系统胶囊压住、长屏顶/底被刘海与 Home 指示条吃掉」的问题。
> 适用工程：`client`（Cocos Creator 3.x，设计分辨率 **720×1280**，`fitWidth:false / fitHeight:true`）。

---

## 1. 背景：真机到底裁哪里

`fitHeight:true` + 720×1280 下，Cocos 的 **Canvas 节点尺寸会自动同步成「可见区」**（长屏上宽度被压到约 591），而 HUD 用 `Widget` 锚定到 Canvas 边 —— 所以 **左右裁切已被 Widget 自动消化**，贴边按钮不会真的飞出屏幕。这一块原工程是对的。

真正没处理的是另一个轴：**Widget 的 `top/bottom/right` 是从物理屏幕边缘量的**，而物理边缘上压着三样东西：

| 区域 | 谁占了 | 改前现状 |
|---|---|---|
| 顶部 | 刘海 / 灵动岛 | `TOP=62` 从物理顶量，长屏上钻进刘海 |
| **右上角** | **抖音系统胶囊**（永远存在） | 金币芯片 `right:22` 正好被胶囊压住 |
| 底部 | Home 指示条 | 道具栏 `bottom:46`，被指示条吃掉一截 |

修复思路：**把宿主的 `safeArea` + 胶囊矩形换算成 720×1280 设计单位的四向内缩，喂进 Widget 的 top/bottom/right。** Canvas 本身无需改动。

## 3. SafeArea.ts（核心工具）

把宿主返回的逻辑 px 换算成设计单位。换算系数 `k = 1280 / screenHeight`（fitHeight 下纵横同系数）。

返回的 `SafeInsets`：

| 字段 | 含义 |
|---|---|
| `top` / `bottom` / `left` / `right` | 四向安全内缩（设计单位） |
| `capsuleBottom` | 屏顶到抖音胶囊下沿的高度 —— 顶栏应从这条线以下开始 |
| `capsuleWidth` | 胶囊宽度 —— 右上元素与胶囊同行时需额外让出 |

关键点：
- 浏览器预览 / 编辑器内拿不到 `tt`，回落到保守值（`capsuleBottom:100 / bottom:34`），与设计稿 `--cap-top:100 / --safe-bottom:34` 对齐，**编辑器里也不穿帮**。
- 优先用 `getMenuButtonBoundingClientRect()` 拿真实胶囊矩形；宿主不支持时回落 `safeArea.top + 标准宽 87`。
- 结果缓存；锁竖屏可忽略，若有 resize / 旋转，回调里调 `SafeArea.invalidate()` 重算。

## 4. GameScene.layoutGameUI() 的接入

```ts
import { SafeArea } from '../platform/SafeArea';

private layoutGameUI(): void {
    this.addBgVeil();
    const safe = SafeArea.get();
    // 顶栏基线 = 胶囊下沿 + 呼吸（无 tt 时回落 62）
    const TOP = Math.max(62, safe.capsuleBottom + 8);

    // 暂停 → 左上：左侧让出 safe.left
    this.anchor(this.btnPause, { top: TOP, left: 26 + safe.left });

    // 道具栏 → 底部：抬到 Home 指示条之上
    this.anchor(group, { bottom: 46 + safe.bottom, hCenter: 0 });

    // 金币芯片 → 右上【本次最实质的修复】：
    // 右侧让出整个胶囊宽度，把芯片推到胶囊左边，不再被压住。
    this.anchor(chip, { top: TOP, right: 22 + safe.right + safe.capsuleWidth + 16 });

    // 订单面板 / 分数 → 用同一 TOP（已含胶囊让位），居中元素横向无需改
    this.anchor(panel, { top: TOP, hCenter: 0 });
    this.anchor(sc,    { top: TOP + 78, hCenter: 6 });

    // NEXT 右侧面板 → 顶部跟随 TOP，右侧让出 safe.right
    this.anchor(panel, { top: TOP + 234, right: 8 + safe.right });
}
```

要点：
- **金币芯片那行是核心修复** —— 原 `right:22` 直接钻进胶囊；`right: 22 + safe.right + safe.capsuleWidth + 16` 把它整体推到胶囊左侧。
- 其余只是给固定 `top/bottom/left/right` 叠加对应 `safe.*`，让最长屏（20:9 安卓 / 灵动岛）也干净。
- `TOP + 234` 等价于改前的绝对 `296`（62+234），保留原视觉、同时随胶囊下移。

## 5. 其余场景同样套（后续）

`HomeScene.ts`、各 `popups/*.ts` 若有贴边按钮：

```ts
const safe = SafeArea.get();
// 顶部贴边
this.anchor(node, { top: someTop + safe.capsuleBottom });
// 底部贴边
this.anchor(node, { bottom: someBottom + safe.bottom });
// 右上关闭按钮避让胶囊
this.anchor(closeBtn, { top: someTop + safe.capsuleBottom, right: someRight + safe.right + safe.capsuleWidth });
```

弹窗多为居中，一般只有「右上关闭按钮」需要避让胶囊。

---

## 6. Canvas 要不要动

**不用。** `720×1280 / fitWidth:false / fitHeight:true` 是对的：Canvas 自动把节点尺寸同步成可见区、Widget 自动吃掉左右裁切。只需确认：

- 所有 HUD 节点都挂在 Canvas 之下（`GameScene` 用 `this.node` 即场景根 Canvas，✓）。
- 背景节点保持 720 宽即可 —— fitHeight 下 720 宽在长屏上是「溢出多覆盖」，不会露边；若担心极端长屏，可把背景拉到 ~810 宽兜底。

---

## 7. 与设计稿的对应关系

设计稿（`ui-redesign/`）已统一到 **720×1280 + 安全带 `[84, 636]` + `--cap-top:100 / --safe-x:84 / --safe-bottom:34`**。引擎侧接入 SafeArea 后两端对齐：

| 设计稿 token | 引擎对应 |
|---|---|
| `--cap-top: 100px` | `safe.capsuleBottom`（顶栏让位） |
| `--safe-bottom: 34px` | `safe.bottom`（底部让位） |
| 安全带 `[84, 636]`（左右各 84） | `safe.left` / `safe.right` + 胶囊宽 |

设计稿的安全带 ≈ 引擎让位后的可用区，做到「设计稿所见 = 真机所得」。

## 8. 验证

1. 抖音开发者工具：切换不同机型（iPhone 15 Pro 灵动岛 / 长屏安卓 20:9），确认金币芯片不再被胶囊压住、暂停与道具栏不被刘海/指示条吃掉。
2. 真机预览：重点看右上角胶囊区与底部 Home 指示条。
3. 编辑器内（无 tt）：回落值生效，布局与设计稿一致，不穿帮。
