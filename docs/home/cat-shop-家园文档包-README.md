## 二、核心设计结论（30 秒回顾）

- **玩法模式 1+4**：合成局产出**猫币** → 回家自由装修 + 收集；**家园不反哺合成数值**（铁律）。
- **单一货币**：猫币。"猫粮"是 V2 宠物养成系统的道具，V1 不做。
- **空间**：可四向滑动、可缩放的大画布世界（非固定竖屏）。
- **装修**：世界坐标网格摆放、不做墙面格、双层规则（地毯层 + 物件层）。
- **店面成长**：主题分区渐进解锁，蓝图 15 区域、首发 6 个、其余 9 个排更新。
- **收集**：家具（区域+稀有度）+ 猫咪（30+ 品种四档稀有度，普通靠里程碑白送、稀有/史诗用猫币领养 + 成就/活动/看广告）。
- **晒图分享**：纯净画面 + 可选相框（游戏名搭相框上），抖音 `shareAppMessage` 带游戏入口、无需二维码。
- **首次引导**：必须做——把冲分玩家拉进家园（首次结算后送启动猫币+首猫+首家具）。

**目标**：确认游戏当前是否已有"猫币/金币"等货币产出逻辑，为家园经济系统的"基础产出"公式定系数。

**让 Claude Code 检查的文件**（工程内 `assets/scenes/scripts/`）：
- `core/ScoreManager.ts` — 计分逻辑，看是否分数之外还产出货币

- `utils/`、`net/` 下与存储相关的代码 — 看本地存储机制（家园数据要复用）

**要回答的问题（已答，详见《设计文档》§十三）**：
1. **每局是否产出货币？** 产出**猫币**，但**按星级查表 5/10/20、仅刷新本关最高星时增量发放、跨局幂等**——不是固定数额、不直接按分数，且**重复刷已通关关卡 0 产出**。10 关全打 3★ 的猫币总产出 = `20×10 = 200`（一次性）。另有局内"金币 gold"：每局初始 15，Lv8 合成 +50、看广告 +10，买锤子/洗牌各 −15，**每局清零、不跨局**。
2. **货币是否有独立字段 + 本地存储？** 猫币 `User.catCoins` 字段**在服务端 Mongo**、由 `POST /api/user/progress` 发放，客户端只镜像内存（`GameState.userProfile.catCoins`）——**不是本地存储**。局内金币 `GameState.gold` 是纯内存、每局重置。（局内一次性 KV 用 `tt.*StorageSync`，每日礼包去重用 `sys.localStorage`。）
3. **是否已接入激励视频？** **是，已全量接入**。`platform/DouyinSDK.showRewardedAd()` + `AdConfig.ts` 定义 5 个广告位：`gameGold`(局内+10金币)、`winDouble`(猫币翻倍·入服务端)、`failRevive`(复活)、`homeCatCoin`(+10猫币·仅内存)、`dailyGift`(每日礼包翻倍·仅内存)。均为**占位 ID**，且 `MOCK_REWARDED_ADS=true`（上线前必须改 false）。
4. **`CustomerManager` 玩法？** 3 槽位上客：顾客排队、同屏 3 位，每位有一组甜品等级需求；玩家合成出对应等级即满足，满足后开心离场、队列补位；队列出完且槽位清空=通关，溢出=失败。10 个猫咪品种作随机皮肤（同屏不重复）。
